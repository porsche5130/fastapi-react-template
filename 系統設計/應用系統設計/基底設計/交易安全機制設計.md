## 核心理念

### 設計原則

> **有使用權 = 需要建立 Token**
>
> Token 包含該使用者對該功能的**所有權限資訊**，前端根據權限決定顯示哪些按鈕。

### 關鍵概念

1. **功能級別的 Token**
   - 每個功能 (func_code) 申請一個 token
   - Token 綁定 `session_id` + `system_functions_id`
   - Token 有效期 30 分鐘，自動延長機制

2. **權限內嵌於 Token**
   - Token 建立時查詢 `role_rights` 取得使用者權限
   - 權限資訊儲存在 Redis 中的 Token 資料
   - API 驗證 Token 時直接讀取權限，**不需要再查資料庫**

3. **三層安全防護**
   - **第一層**: Session Token (Bearer Token) 驗證身份
   - **第二層**: Transaction Token (X-Txn-Token) 驗證功能存取權
   - **第三層**: Permission Check (Token 內權限) 驗證操作權限

## 交易令牌機制總覽

### 正確流程

```
1. 使用者進入頁面
   └─> POST /api/transaction/request {"func_code": "user_roles"}
   └─> 查詢 role_rights 取得權限
   └─> 建立 Token 並存入 Redis (包含 permissions)
   └─> 回傳 {txn_token, permissions}

2. 前端根據 permissions 決定顯示按鈕
   - permissions.read → 顯示列表、檢視按鈕
   - permissions.create → 顯示新增按鈕
   - permissions.update → 顯示編輯按鈕
   - permissions.delete → 顯示刪除按鈕

3. 呼叫 API 時帶 Token
   GET /api/user_roles (Header: X-Txn-Token)
   └─> verify_txn_token 驗證並取得 permissions
   └─> 檢查 permissions.read
   └─> 通過 ✅

   POST /api/user_roles (Header: X-Txn-Token)
   └─> verify_txn_token 驗證並取得 permissions
   └─> 檢查 permissions.create
   └─> 通過 ✅
```

## 權限類型

| 權限代碼 | 英文名稱 | 中文名稱 | 對應操作 | HTTP Method |
|---------|---------|---------|---------|-------------|
| `create` | Create | 新增 | 建立資料 | POST |
| `read` | Read | 讀取 | 查詢資料 | GET |
| `update` | Update | 修改 | 更新資料 | PUT/PATCH |
| `delete` | Delete | 刪除 | 刪除資料 | DELETE |
| `print` | Print | 列印 | 匯出報表 | GET (特定端點) |
| `file` | File | 檔案 | 檔案上傳/下載 | POST/GET (檔案) |

## API 端點規範

### 重要規則

1. ✅ **所有端點都需要 Token** (包括 GET)
2. ✅ **GET → read 權限**
3. ✅ **POST → create 權限**
4. ✅ **PUT/PATCH → update 權限**
5. ✅ **DELETE → delete 權限 + one_time_use=True**
6. ❌ **不要再使用 `check_permission` 手動檢查** (Token 已驗證)
7. ✅ **所有 API 文件都要說明需要的權限**

### GET 端點範例 (查詢) - 需要 read 權限

```python
@router.get("/", response_model=List[UserRoleResponse])
async def get_user_roles(
    skip: int = 0,
    limit: int = 100,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
    _token: None = Depends(require_txn_token("user_roles", "read"))
):
    """
    取得使用者角色列表

    需要 user_roles 功能的 read 權限
    需要提供 Bearer Token 及 X-Txn-Token Header
    """
    # Token 已驗證權限，直接執行業務邏輯
    query = db.query(UserRole)
    roles = query.order_by(UserRole.id).offset(skip).limit(limit).all()
    return roles
```

### POST 端點範例 (新增) - 需要 create 權限

```python
@router.post("/", response_model=UserRoleResponse, status_code=201)
async def create_user_role(
    role_data: UserRoleCreate,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
    _token: None = Depends(require_txn_token("user_roles", "create"))
):
    """
    建立使用者角色

    需要 user_roles 功能的 create 權限
    需要提供 Bearer Token 及 X-Txn-Token Header
    """
    # Token 已驗證權限，不需要再次檢查
    role = UserRole(**role_data.model_dump(), edit_by=current_user.id)
    db.add(role)
    db.commit()
    db.refresh(role)
    return role
```

### PUT 端點範例 (更新) - 需要 update 權限

```python
@router.put("/{role_id}", response_model=UserRoleResponse)
async def update_user_role(
    role_id: int,
    role_data: UserRoleUpdate,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
    _token: None = Depends(require_txn_token("user_roles", "update"))
):
    """
    更新使用者角色

    需要 user_roles 功能的 update 權限
    需要提供 Bearer Token 及 X-Txn-Token Header
    """
    # Token 已驗證權限，不需要再次檢查
    role = db.query(UserRole).filter(UserRole.id == role_id).first()
    if not role:
        raise HTTPException(404, "找不到使用者角色")
    # 更新邏輯...
    return role
```

### DELETE 端點範例 (刪除) - 需要 delete 權限 + 一次性使用

```python
@router.delete("/{role_id}", status_code=204)
async def delete_user_role(
    role_id: int,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user),
    _token: None = Depends(require_txn_token("user_roles", "delete", one_time_use=True))
):
    """
    刪除使用者角色

    需要 user_roles 功能的 delete 權限
    此操作為一次性使用，Token 使用後立即失效
    需要提供 Bearer Token 及 X-Txn-Token Header
    """
    # Token 已驗證權限，且使用後立即失效
    role = db.query(UserRole).filter(UserRole.id == role_id).first()
    if not role:
        raise HTTPException(404, "找不到使用者角色")
    db.delete(role)
    db.commit()
    return None
```

## 錯誤處理

| HTTP Status | 錯誤情境 | 說明 |
|-------------|---------|------|
| 401 Unauthorized | Token 無效或過期 | 請重新申請 Token |
| 401 Unauthorized | 缺少 Session Token | 請重新登入 |
| 403 Forbidden | 無功能存取權 | 該使用者無任何權限 |
| 403 Forbidden | 無操作權限 | Token 有效但缺少該操作權限 |
| 403 Forbidden | Session 不符 | Token 與當前 Session 不符 |
| 404 Not Found | 功能不存在 | 系統功能未註冊 |

## 安全考量

### Token 安全
- ✅ **綁定 Session**: Token 與 session_id 綁定，無法跨 Session 使用
- ✅ **有效期限制**: 30 分鐘自動過期
- ✅ **一次性使用**: DELETE 操作使用後立即失效
- ✅ **SHA256 雜湊**: Token 使用 SHA256 產生，無法預測
- ✅ **Redis 儲存**: 使用 Redis TTL 自動清理過期 Token

### 權限安全
- ✅ **最小權限原則**: 使用者只能取得 role_rights 中定義的權限
- ✅ **權限快照**: Token 建立時快照權限，避免中途權限變更
- ✅ **禁止權限提升**: Token 中的權限不可修改或偽造

### 防止攻擊
- ✅ **CSRF 防護**: Token 存在 Header (X-Txn-Token)，非 Cookie
- ✅ **XSS 防護**: Token 僅在記憶體，不存 localStorage
- ✅ **重放攻擊**: DELETE 使用一次性 Token
- ✅ **暴力破解**: Token 使用強雜湊，無法暴力破解
