## 2. 核心功能模組

### 2.1 認證授權模組 (Authentication & Authorization)

#### 功能說明
處理使用者身份驗證、授權與會話管理。

#### 主要功能
1. **使用者登入/登出**
   - 使用者透過 `account` (帳號) 與密碼登入
   - 密碼使用 bcrypt 雜湊加密儲存
   - 登入成功後核發 JWT Access Token
   - 記錄登入時間 (`last_login_at`) 與 IP (`last_login_ip`)

2. **Token 管理**
   - Access Token 有效期: 24 小時
   - Token 包含使用者 ID (sub)、帳號、角色等資訊
   - 使用 HTTP Bearer Token 進行 API 認證

3. **權限控制**
   - 基於角色的存取控制 (RBAC)
   - 功能層級的權限設定 (Create/Read/Update/Delete/Print/File)
   - 動態權限檢查機制

#### 相關檔案
- **後端**:
  - `app/routes/auth.py` - 認證路由
  - `app/core/security.py` - JWT 加密/解密
  - `app/core/deps.py` - 依賴注入 (get_current_user)
  - `app/schemas/auth.py` - 認證相關 Schema

- **前端**:
  - `src/contexts/AuthContext.tsx` - 認證狀態管理
  - `src/api/authService.ts` - 認證 API 服務
  - `src/pages/LoginPage.tsx` - 登入頁面
  - `src/components/PrivateRoute.tsx` - 路由守衛

#### 資料表
- `users` - 使用者基本資料與認證資訊
- `user_logs` - 使用者登入/登出記錄

### 2.2 系統功能管理模組 (System Function Management)

#### 功能說明
管理系統功能選單的樹狀結構、權限設定與動態路由配置。

#### 主要功能
1. **功能樹狀結構管理**
   - 支援多層級功能節點
   - 節點類型 (Node) vs 功能類型 (Function)
   - 自訂排序順序

2. **權限配置**
   - 為每個功能設定可用操作權限
   - 權限類型: Create, Read, Update, Delete, Print, File
   - 僅功能類型可設定權限，節點類型不可設定

3. **動態路由**
   - 根據 `module_code` 動態產生路由
   - 整合 React Router 進行前端路由管理

4. **多語系支援**
   - 中文名稱 (`func_cname`)
   - 英文名稱 (`func_ename`)
   - 權限操作名稱國際化

#### 相關檔案
- **後端**:
  - `app/routes/system_functions.py` - 系統功能路由
  - `app/models/system_functions.py` - 系統功能模型
  - `app/schemas/system_functions.py` - 系統功能 Schema

- **前端**:
  - `src/pages/SysFunctionsPage.tsx` - 系統功能管理頁面
  - `src/services/sysFunctionService.ts` - 系統功能 API 服務

#### 資料表結構
```sql
Table: system_functions
-- 主鍵
- id SERIAL PRIMARY KEY

-- 功能資訊
- func_code VARCHAR(200) NOT NULL           -- 功能代碼
- upper_func_id INTEGER NOT NULL DEFAULT 0  -- 上層功能ID (0表示根節點)
- func_cname VARCHAR(200) NOT NULL          -- 功能中文名稱
- func_ename VARCHAR(200) NOT NULL          -- 功能英文名稱
- func_type INTEGER NOT NULL                -- 功能類型 (1=節點, 2=功能)
- func_order INTEGER NOT NULL               -- 排序順序
- func_icon VARCHAR(200)                    -- 圖示

-- 模組資訊
- module_code VARCHAR(200)             -- 模組路徑 (節點為NULL)
- module_item JSONB NOT NULL DEFAULT '[]'   -- 可設定權限 JSON 陣列

-- 說明與狀態
- description TEXT                          -- 功能說明 (富文本格式)
- is_mana BOOLEAN NOT NULL DEFAULT FALSE    -- 是否為管理功能
- is_active BOOLEAN NOT NULL DEFAULT TRUE   -- 是否啟用

-- 系統欄位
- edit_by INTEGER NOT NULL                  -- 最後編輯者 (FK -> users.id)
- created_at TIMESTAMP NOT NULL             -- 建立時間
- updated_at TIMESTAMP                      -- 更新時間

Constraints:
- chk_func_type: func_type IN (1, 2)
- chk_func_module:
  - func_type=1 時，module_code 必須為 NULL
  - func_type=2 時，module_code 不可為 NULL

Indexes:
- idx_system_functions_code ON func_code
- idx_system_functions_upper ON upper_func_id
- idx_system_functions_type ON func_type
- idx_system_functions_active ON is_active
- idx_system_functions_order ON func_order
```

#### 業務邏輯規則
1. **節點類型 (func_type=1)**:
   - `module_code` 必須為 NULL
   - `module_item` 應為空陣列
   - 前端 UI 自動禁用相關欄位

2. **功能類型 (func_type=2)**:
   - `module_code` 必須有值 (例如: "users", "settings")
   - `module_item` 可包含一個或多個權限字串
   - 前端根據模組名稱產生路由: `/system/${module_code}`

3. **空字串處理**:
   - 前端在提交前將空字串轉換為 `undefined`
   - 後端 Pydantic 將 `None` 序列化為資料庫 `NULL`

### 2.3 使用者管理模組 (User Management)

#### 功能說明
管理系統使用者的基本資料、角色指派與狀態控制。

#### 主要功能
1. **使用者 CRUD**
   - 建立、查詢、更新、刪除使用者
   - 使用者資料包含: 帳號、使用者名稱、密碼、組織、角色、部門、職稱、電話
   - 支援批次查詢與關鍵字搜尋

2. **帳號管理**
   - 使用 `account` 欄位作為登入帳號 (UNIQUE)
   - `username` 欄位儲存顯示名稱
   - 每個使用者帳號必須唯一

3. **密碼管理**
   - 新增使用者時設定初始密碼
   - 密碼使用 bcrypt 加密存儲
   - 密碼不可透過 API 查詢

4. **登入追蹤**
   - `last_login_at`: 記錄最後登入時間
   - `last_login_ip`: 記錄最後登入IP位址
   - 協助安全監控與異常登入偵測

5. **狀態管理**
   - 啟用/停用使用者帳號 (`is_active`)
   - 停用後無法登入系統

6. **組織與角色關聯**
   - 每個使用者必須隸屬於一個組織 (`organization_id`)
   - 透過 `user_roles` (JSONB 陣列) 儲存使用者的角色ID
   - 支援多角色配置

#### 相關檔案
- **後端**:
  - `app/routes/users.py` - 使用者路由
  - `app/models/users.py` - 使用者模型
  - `app/schemas/users.py` - 使用者 Schema

- **前端**:
  - `src/pages/UsersPage.tsx` - 使用者管理頁面
  - `src/services/userDetailService.ts` - 使用者 API 服務

#### 資料表結構
```sql
Table: users
-- 主鍵
- id SERIAL PRIMARY KEY

-- 組織與帳號
- organization_id INTEGER NOT NULL          -- 組織編號 (FK -> organizations.id)
- account VARCHAR(100) UNIQUE NOT NULL      -- 登入帳號
- username VARCHAR(200) NOT NULL            -- 使用者名稱
- password VARCHAR(200) NOT NULL            -- 使用者密碼 (bcrypt hash)

-- 職務資訊
- department VARCHAR(200)                   -- 所屬部門
- job_title VARCHAR(200)                    -- 職稱
- phone VARCHAR(200)                        -- 連絡電話

-- 角色權限
- user_roles JSONB NOT NULL DEFAULT '[]'     -- 所屬角色 JSON 陣列 [user_roles.id]

-- 登入資訊
- last_login_at TIMESTAMP                   -- 最後登入時間
- last_login_ip VARCHAR(100)                -- 最後登入IP

-- 系統欄位
- is_active BOOLEAN NOT NULL DEFAULT TRUE   -- 啟用
- edit_by INTEGER NOT NULL                  -- 編輯者 (FK -> users.id)
- created_at TIMESTAMP NOT NULL             -- 建立時間
- updated_at TIMESTAMP                      -- 修改時間

Foreign Keys:
- organization_id -> organizations(id)
- edit_by -> users(id)

Indexes:
- idx_users_account ON account (UNIQUE)
- idx_users_org ON organization_id
- idx_users_active ON is_active
```

### 2.4 角色管理模組 (User Role Management)

#### 功能說明
定義使用者角色與功能權限的對應關係。

#### 主要功能
1. **角色 CRUD**
   - 建立、查詢、更新、刪除角色
   - 角色包含: 中英文名稱、說明

2. **角色類型**
   - `is_mana`: 標記是否為管理角色
   - 管理角色擁有較高的系統權限

3. **角色指派**
   - 使用者建立時指派一個或多個角色
   - 角色ID 儲存在 `users.user_roles` 欄位 (JSONB 陣列)
   - 一個使用者可以擁有多個角色

4. **權限控制**
   - 系統根據使用者的角色ID，結合 `system_functions.module_item` 決定使用者可執行的操作
   - 透過後端中介軟體進行權限驗證

#### 相關檔案
- **後端**:
  - `app/routes/user_roles.py` - 角色路由
  - `app/models/user_roles.py` - 角色模型
  - `app/schemas/user_roles.py` - 角色 Schema

- **前端**:
  - `src/pages/UserRolesPage.tsx` - 角色管理頁面
  - `src/services/userRolesService.ts` - 角色 API 服務

#### 資料表結構
```sql
Table: user_roles
-- 主鍵
- id SERIAL PRIMARY KEY

-- 角色資訊
- role_cname VARCHAR(200) NOT NULL          -- 角色中文名稱
- role_ename VARCHAR(200) NOT NULL          -- 角色英文名稱
- description TEXT                          -- 說明 (富文本格式)

-- 系統欄位
- is_mana BOOLEAN NOT NULL DEFAULT FALSE    -- 是否為管理角色
- is_active BOOLEAN NOT NULL DEFAULT TRUE   -- 是否啟用
- edit_by INTEGER NOT NULL                  -- 編輯者 (FK -> users.id)
- created_at TIMESTAMP NOT NULL             -- 建立時間
- updated_at TIMESTAMP                      -- 修改時間

Foreign Keys:
- edit_by -> users(id)

Indexes:
- idx_user_roles_active ON is_active

注意: 角色的權限設定儲存在 users.user_roles 欄位中，格式為 JSONB 陣列包含角色ID
```

### 2.5 組織管理模組 (Organization Management)

#### 功能說明
管理系統中的組織架構與基本資料。

#### 主要功能
1. **組織 CRUD**
   - 建立、查詢、更新、刪除組織
   - 組織資料: 統編/代碼、組織名稱、組織型態

2. **組織型態**
   - 1: 政府機關
   - 2: 公司行號
   - 3: 個人

3. **聯絡資訊管理**
   - 連絡人姓名、郵件、電話
   - 組織地址、代表號

4. **系統管理公司**
   - `is_mana` 標記系統管理公司 (只能有一家為 TRUE)
   - 系統管理公司負責整體系統維運

5. **組織關聯**
   - 使用者必須隸屬於組織 (`users.organization_id`)
   - 組織可包含多個使用者
   - 系統設定中記錄管理公司 (`sys_profile.sys_organization`)

#### 相關檔案
- **後端**:
  - `app/routes/organization.py` - 組織路由
  - `app/models/organization.py` - 組織模型
  - `app/schemas/organization.py` - 組織 Schema

- **前端**:
  - `src/pages/OrganizationsPage.tsx` - 組織管理頁面
  - `src/services/organizationService.ts` - 組織 API 服務

#### 資料表結構
```sql
Table: organizations
-- 主鍵
- id SERIAL PRIMARY KEY

-- 組織資訊

- is_mana BOOLEAN NOT NULL DEFAULT FALSE    -- 系統管理公司 (只有一家可設為 TRUE)
- is_active BOOLEAN NOT NULL DEFAULT TRUE   -- 啟用
- memo VARCHAR(1000)                        -- 備註
- edit_by INTEGER NOT NULL                  -- 編輯者 (FK -> users.id)
```

### 2.6 系統設定模組 (System Profile)

#### 功能說明
管理系統層級的配置參數，支援多語系與動態設定。

#### 主要功能
1. **系統狀態管理**
   - `is_service`: 控制系統是否正常服務
   - TRUE: 正常運作
   - FALSE: 維護模式

2. **系統基本資訊**
   - 系統網址 (`sys_url`)
   - 系統中文標題 (`sys_ctitle`)
   - 系統英文標題 (`sys_etitle`)
   - 系統中文版權宣告 (`sys_ccopyright`)
   - 系統英文版權宣告 (`sys_ecopyright`)

3. **系統管理設定**
   - 系統管理公司 (`sys_organization`) - 關聯至 organizations
   - 系統管理員電子郵件 (`sys_mana_email`)

4. **多語系支援**
   - 透過 API 提供系統標題與版權資訊的多語系版本
   - 前端根據語言設定顯示對應文字

5. **靜態資源管理**
   - Logo、圖片儲存於 `/images` 目錄
   - 上傳檔案儲存於 `/uploads` 目錄
   - 語系檔案儲存於 `/locales` 目錄
   - 透過 FastAPI StaticFiles 提供靜態資源服務

6. **唯一性約束**
   - 此表只能有一筆資料 (id=1)
   - 透過 CHECK 約束確保

#### 相關檔案
- **後端**:
  - `app/routes/sys_profile.py` - 系統設定路由
  - `app/models/sys_profile.py` - 系統設定模型
  - `app/schemas/sys_profile.py` - 系統設定 Schema

- **前端**:
  - `src/pages/SysProfilePage.tsx` - 系統設定頁面
  - `src/services/sysProfileService.ts` - 系統設定 API 服務
  - `src/contexts/SystemContext.tsx` - 系統設定狀態管理

### 2.7 作業記錄模組 (User Logs)

#### 功能說明
記錄所有使用者在系統中的操作行為，用於審計追蹤與問題排查。

#### 主要功能
1. **操作記錄**
   - 記錄使用者對每個功能的操作
   - 記錄操作類型: Create, Read, Update, Delete, Print, File
   - 記錄操作時間與IP位址

2. **資料追蹤**
   - `look_data`: 記錄檢視的資料內容 (JSON格式)
   - `change_data`: 記錄異動的資料內容 (JSON格式)
   - 支援資料差異比對

3. **錯誤記錄**
   - 記錄操作失敗的錯誤訊息
   - 協助問題排查與系統監控

4. **審計查詢**
   - 依使用者查詢操作歷史
   - 依功能查詢使用記錄
   - 依時間範圍查詢操作記錄

#### 相關檔案
- **後端**:
  - `app/models/user_logs.py` - 作業記錄模型

#### 資料表結構
```sql
Table: user_logss
-- 主鍵
- id SERIAL PRIMARY KEY

-- 作業資訊
- users_id INTEGER NOT NULL          -- 作業人員 (FK -> users.id)
- system_functions_id INTEGER NOT NULL           -- 作業功能 (FK -> system_functions.id)
- module_item VARCHAR(50) NOT NULL         -- 模組項目 (Create/Read/Update/Delete/Print/File)

-- 資料記錄
- look_data JSONB NOT NULL DEFAULT '{}'    -- 檢視資料 (JSON 格式: {欄位名稱: 資料內容})
- change_data JSONB NOT NULL DEFAULT '{}'  -- 異動資料 (JSON 格式: {欄位名稱: 資料內容})

-- 時間與錯誤
- action_at TIMESTAMP NOT NULL             -- 作業時間
- err_detail VARCHAR(2000)                 -- 異常紀錄

Constraints:
- chk_module_item: module_item IN ('Create', 'Read', 'Update', 'Delete', 'Print', 'File')

Foreign Keys:
- users_id -> users(id)
- system_functions_id -> system_functions(id)

Indexes:
- idx_user_logss_user ON users_id
```

## 6. 安全性設計

### 6.1 認證機制

#### JWT Token 設計
```python
# Token Payload (實際內容)
{
  "sub": "1",              # 使用者 ID (users.id) - 必須為字串格式
  "exp": 1737273600        # 過期時間 (Unix timestamp)
}

# Token 簽章設定
SECRET_KEY = "your-secret-key"     # 從環境變數載入
ALGORITHM = "HS256"                # 使用 HS256 演算法
ACCESS_TOKEN_EXPIRE_MINUTES = 1440 # 24小時 = 1440分鐘

# Token 生成流程
1. 使用者登入驗證成功
2. 建立 payload: {"sub": str(user.id)}
3. 加上過期時間 exp (當前時間 + 1440分鐘)
4. 使用 SECRET_KEY 和 HS256 演算法編碼
5. 回傳給前端: {"access_token": "...", "token_type": "bearer"}

# Token 驗證流程
1. 前端在 Header 帶入: Authorization: Bearer <token>
2. 後端解碼 token 取得 sub (user_id)
3. 從資料庫查詢使用者資料
4. 檢查使用者是否啟用 (is_active)
5. 將使用者物件注入到 API 函數
```

#### 密碼加密
```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 加密密碼
hashed = pwd_context.hash(plain_password)

# 驗證密碼
pwd_context.verify(plain_password, hashed_password)
```
