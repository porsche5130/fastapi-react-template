# 路由架構設計

## 概述

本系統採用前後端分離架構，路由設計統一使用 `module_code` 作為 API 路徑標準。

## 核心原則

- **前端路由**：使用 `func_code` 作為路徑（反映功能語意）
- **後端 API 路由**：使用 `module_code` 作為路徑（對應模組）
- **模組設計**：一個模組可包含單一或多個資料表
- **靈活性**：`func_code` 和 `module_code` 可以不同，提供最大彈性

## sysfunction 資料表欄位說明

### func_code (功能代碼)
- **用途**：功能唯一識別碼
- **格式**：小寫英文，可使用底線 `_`
- **命名規則**：
  - 操作多筆物件時用**複數**（例如：`invoices`）
  - 操作單一物件時用**單數**（例如：`my_profile`）
- **使用場景**：
  - 使用者權限檢查的功能識別碼
  - 日誌記錄的功能識別
  - 前端路由路徑（`/{func_code}`）
  - 前端頁面檔名（去除底線，轉 PascalCase + Page.tsx）

**前端檔名轉換範例**：
- `system_codes` → `SystemCodesPage.tsx`
- `user_detail` → `UserDetailPage.tsx`
- `my_organization` → `MyOrganizationPage.tsx`

### module_code (模組代碼)
- **用途**：模組唯一識別碼
- **格式**：小寫英文，可使用底線 `_`
- **命名規則**：依模組功能範圍命名
- **使用場景**：
  - 後端 FastAPI 路由前綴（`/api/{module_code}`）
  - 模組物件識別
  - 在模組內部定義處理的資料表

**模組物件定義**：
1. **單一資料表模組**：
   - `module_code` = 資料表名稱
   - 例如：`module_code = 'system_codes'` 對應資料表 `system_codes`

2. **多資料表模組**（Master-Detail 或複雜模組）：
   - `module_code` 代表模組名稱
   - 在模組內部（Model/Router 層）定義處理多個資料表
   - 例如：`module_code = 'invoices'`
     - 處理 `invoice` (Master) 和 `invoice_item` (Detail)
     - 透過 ORM relationship 和巢狀 API 管理關聯

### func_code 與 module_code 的關係

**核心原則**：`func_code` 和 `module_code` **可以不同**

這提供了最大的靈活性：
- 不同功能（不同的 `func_code`）可以操作同一個模組（相同的 `module_code`）
- 一個模組（`module_code`）可以包含多個資料表的處理邏輯

## 實作範例

### 範例 1：單一資料表模組

```sql
INSERT INTO sysfunction (
    func_code,              -- 'system_codes'
    module_code,            -- 'system_codes'
    func_cname,             -- '系統代碼設定'
    func_ename,             -- 'System Codes'
    ...
) VALUES (
    'system_codes',
    'system_codes',
    '系統代碼設定',
    'System Codes',
    ...
);
```

**對應結構**：
- 前端路由：`/system_codes`
- 後端 API：`/api/system_codes`
- 前端頁面：`SystemCodesPage.tsx`
- 資料表：`system_codes` (1個)

### 範例 2：多資料表模組（Master-Detail）

```sql
INSERT INTO sysfunction (
    func_code,              -- 'invoices'
    module_code,            -- 'invoices'
    func_cname,             -- '發票管理'
    func_ename,             -- 'Invoice Management'
    memo,                   -- '管理發票主檔(invoice)及明細(invoice_item)'
    ...
) VALUES (
    'invoices',
    'invoices',
    '發票管理',
    'Invoice Management',
    '管理發票主檔(invoice)及明細(invoice_item)',
    ...
);
```

**對應結構**：
- 前端路由：`/invoices`
- 後端 API：
  - `/api/invoices` (Master)
  - `/api/invoices/{id}/items` (Detail，巢狀路由)
- 前端頁面：`InvoicesPage.tsx` (包含 Master 和 Detail UI)
- 資料表：
  - `invoice` (Master)
  - `invoice_item` (Detail)

**Model 層定義**：
```python
# app/models/invoice.py
class Invoice(Base):
    __tablename__ = "invoice"
    items = relationship("InvoiceItem", back_populates="invoice")

class InvoiceItem(Base):
    __tablename__ = "invoice_item"
    invoice_id = Column(Integer, ForeignKey("invoice.id"))
    invoice = relationship("Invoice", back_populates="items")
```

### 範例 3：共用模組（不同功能，不同模組）

```sql
-- 功能 1：系統管理員用
INSERT INTO sysfunction (
    func_code,              -- 'org_profile' (管理多個組織)
    module_code,            -- 'org_profile'
    func_cname,             -- '組織資料維護'
    ...
) VALUES (...);

-- 功能 2：一般使用者用
INSERT INTO sysfunction (
    func_code,              -- 'organizations' (管理多個組織)
    module_code,            -- 'organizations'
    func_cname,             -- '組織管理'
    ...
) VALUES (...);
```

**對應結構**：

| 項目 | 功能 1 (管理員) | 功能 2 (使用者) |
|------|---------------|---------------|
| func_code | org_profile | organizations |
| module_code | org_profile | organizations |
| 前端路由 | /org_profile | /organizations |
| 後端 API | /api/org_profile | /api/organizations |
| 前端頁面 | OrgProfilePage.tsx | OrganizationsPage.tsx |
| 資料表 | organization | organization (共用) |
| 資料範圍 | 所有組織 | 自己所屬組織 |

**注意**：兩個功能各自有獨立的 Router，但在 Model 層共用同一個 `Organization` Model。

### 範例 4：單一物件功能

```sql
INSERT INTO sysfunction (
    func_code,              -- 'my_profile' (單數，操作單一物件)
    module_code,            -- 'user_profiles'
    func_cname,             -- '我的個人資料'
    ...
) VALUES (...);
```

**對應結構**：
- 前端路由：`/my_profile`
- 後端 API：`/api/user_profiles/{current_user_id}`
- 前端頁面：`MyProfilePage.tsx`
- 資料表：`user_profile`
- 說明：`func_code` 用單數表示「操作單一物件」

## 命名規範

### 標準格式
1. **使用小寫英文**
2. **單字間使用底線 `_` 分隔**
3. **避免使用縮寫**（除非是業界通用縮寫，如 API, URL）
4. **保持語意清晰**
5. **func_code 依操作物件數量決定單複數**
6. **module_code 依模組範圍命名**

### 好的範例
- `system_codes` ✅（系統代碼，複數）
- `user_logs` ✅（使用者日誌，複數）
- `my_profile` ✅（我的資料，單數）
- `invoices` ✅（發票，複數，包含 Master-Detail）

### 不建議的範例
- `sysCodes` ❌（駝峰式，不符合資料庫命名慣例）
- `systemcode` ❌（沒有底線，不易閱讀）
- `sys_cd` ❌（過度縮寫，語意不清）
- `SYS_CODES` ❌（全大寫，Python/JavaScript 慣例不使用）

## 開發檢查清單

新增功能時，請確認以下項目：

- [ ] `func_code` 命名符合規範（複數/單數依操作物件數量）
- [ ] `module_code` 命名符合規範（對應模組範圍）
- [ ] 前端路由使用 `func_code`
- [ ] Sidebar 選單使用 `func_code`
- [ ] 後端 API 路由使用 `module_code`
- [ ] 前端 Service API 路徑使用 `module_code`
- [ ] 權限檢查使用 `func_code`
- [ ] 日誌記錄使用 `func_code`
- [ ] 前端頁面檔名符合轉換規則（去除底線 + PascalCase + Page.tsx）
- [ ] 如為 Master-Detail，在 Model 層定義 relationship
- [ ] 如為 Master-Detail，使用巢狀 API 路由
