# 系統代碼進階用法

## 概述

`system_codes` 資料表不僅用於管理一般的系統代碼，也可以用來存放**系統參數設定**。透過 `category`（類別）來區分不同用途，`note1` ~ `note5` 欄位可彈性存放說明或參數值。

## 資料表結構

```sql
CREATE TABLE system_codes (
    id SERIAL PRIMARY KEY,
    category VARCHAR(50) NOT NULL,           -- 類別代碼
    code VARCHAR(50) NOT NULL,               -- 代碼
    cname VARCHAR(200) NOT NULL,             -- 中文名稱
    ename VARCHAR(200),                      -- 英文名稱
    sort_order INTEGER DEFAULT 0,            -- 排序順序
    note1 VARCHAR(500),                      -- 備註1 / 參數值1
    note2 VARCHAR(500),                      -- 備註2 / 參數值2
    note3 VARCHAR(500),                      -- 備註3 / 參數值3
    note4 VARCHAR(500),                      -- 備註4 / 參數值4
    note5 VARCHAR(500),                      -- 備註5 / 參數值5
    is_active BOOLEAN DEFAULT TRUE,          -- 是否啟用
    edit_by INTEGER,                         -- 編輯者
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP
);
```

## 欄位說明

### note1 ~ note5 的使用建議

#### 作為「參數值」使用時
- **note1**: 主要參數值
- **note2**: 參數說明或可選值
- **note3**: 備用參數值或額外說明
- **note4**: 進階參數值
- **note5**: 其他說明或預留

#### 作為「代碼說明」使用時
- **note1**: 主要說明
- **note2**: 次要說明
- **note3**: 使用注意事項
- **note4**: 相關說明
- **note5**: 其他備註

## API 使用範例

### 後端 API

```python
# 取得特定類別的所有代碼
GET /api/system_codes?category=ORG_TYPE

# 取得特定代碼的詳細資訊
GET /api/system_codes?category=SYS_PARAM&code=DEFAULT_LANG

# 新增代碼
POST /api/system_codes
{
    "category": "SYS_PARAM",
    "code": "MAX_LOGIN_ATTEMPTS",
    "cname": "最大登入嘗試次數",
    "ename": "Max Login Attempts",
    "note1": "5",
    "note2": "超過此次數將鎖定帳號",
    "is_active": true
}

# 更新代碼
PUT /api/system_codes/{id}
{
    "note1": "3",
    "note2": "已調整為3次"
}
```

### 前端使用

```typescript
// 取得系統參數
const getSystemParam = async (code: string): Promise<string | null> => {
  const response = await axios.get('/api/system_codes', {
    params: {
      category: 'SYS_PARAM',
      code: code
    }
  });
  return response.data[0]?.note1 || null;
};

// 使用範例
const defaultLang = await getSystemParam('DEFAULT_LANG');
const pageSize = await getSystemParam('PAGE_SIZE');

// 取得下拉選單選項
const getCodeOptions = async (category: string) => {
  const response = await axios.get('/api/system_codes', {
    params: { category }
  });
  return response.data.map((item: any) => ({
    value: item.code,
    label: item.cname
  }));
};

// 使用範例
const orgTypeOptions = await getCodeOptions('ORG_TYPE');
// [{ value: 'GOV', label: '政府機關' }, ...]
```

## 設計優勢

1. **彈性**: note1~note5 可根據不同需求彈性運用
2. **統一管理**: 所有代碼和參數都在同一個表，方便維護
3. **可擴展**: 透過 category 輕鬆增加新的代碼類別
4. **版本控制**: 透過 updated_at 追蹤參數變更歷史
5. **權限控制**: 可針對不同 category 設定不同的存取權限
6. **多語系**: 透過 cname 和 ename 支援多語系

## 使用建議

### 適合用 system_codes 的情境
- 下拉選單選項
- 狀態代碼
- 類型代碼
- 系統全域參數
- 不需要複雜邏輯的設定值

### 不適合用 system_codes 的情境
- 需要複雜資料結構的設定
- 需要關聯其他資料表的設定
- 需要頻繁變更的業務邏輯
- 敏感資訊（如密碼、金鑰等，應另外設計）
