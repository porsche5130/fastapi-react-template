# 共用資料表設計

## 概述

當多個功能需要操作同一個資料表，但有不同的業務邏輯和權限控制時，使用本設計模式。

## 核心原則

1. **不同的 func_code**：每個功能有獨立的 func_code 用於權限識別和前端路由
2. **不同的 module_code**：每個功能有獨立的 API 路由路徑
3. **共用的資料表**：在後端 Model 層，不同的 module 對應到同一個資料表
4. **不同的業務邏輯**：根據使用者角色和功能實作不同的過濾條件

## 架構設計

**核心策略：不同的功能使用不同的 func_code 和 module_code，在 Model/Service 層共用同一個資料表！**

```
功能1（管理員用）:
  func_code = 'org_profile'        → 權限識別、前端路由
  module_code = 'org_profile'      → API 路由識別
  前端路由 = /org_profile
  後端 API = /api/org_profile
  資料表 = organization (在 Model 層對應)

功能2（一般使用者用）:
  func_code = 'organizations'      → 權限識別、前端路由
  module_code = 'organizations'    → API 路由識別
  前端路由 = /organizations
  後端 API = /api/organizations
  資料表 = organization (在 Model 層對應，與功能1相同！)
```

**關鍵設計：**
1. 不同的 func_code 和 module_code（每個功能獨立）
2. 不同的路由、不同的 Router
3. **在後端 Model/Service 層共用同一個 Organization Model**
4. 透過 Service 的業務邏輯參數區分不同的資料範圍

## 實作範例：組織資料管理

### 場景說明

系統有兩個組織管理功能：

1. **org_profile（組織資料維護）**
   - 目標使用者：系統管理員
   - 權限：可以查看和維護**所有組織**的資料
   - 位置：系統管理選單下
   - 功能：完整的 CRUD 操作

2. **organizations（組織管理）**
   - 目標使用者：一般使用者
   - 權限：只能查看和修改**自己所屬組織**的資料
   - 位置：主選單下
   - 功能：有限的 CRUD 操作（受限於所屬組織）

### 資料庫配置

```sql
-- 功能 1：組織資料維護（系統管理員用）
INSERT INTO sysfunction (

    func_ename,             -- 'Organization Management'
    ...

```

**共用資料表：`organization`**

**關鍵設計：**
- 兩個功能有不同的 func_code 和 module_code
- 兩個功能有不同的路由和權限識別
- **在後端 Model 層，兩個 Router 都使用同一個 Organization Model**

```python
# app/services/organization_service.py

class OrganizationService:
    """組織資料服務（共用）"""

    async def get_all(
        self,
        db: Session,
        user_org_id: Optional[int] = None,  # 使用者所屬組織ID
        is_admin: bool = False               # 是否為管理員
    ) -> List[Organization]:
        """
        取得組織列表
        - 管理員：可以看到所有組織
        - 一般使用者：只能看到自己所屬的組織
        """
        query = db.query(Organization)

        if not is_admin and user_org_id:
            # 一般使用者：過濾只顯示自己的組織
            query = query.filter(Organization.id == user_org_id)

        return query.all()

    async def update(
        self,
        db: Session,
        org_id: int,
        data: OrganizationUpdate,
        user_org_id: Optional[int] = None,
        is_admin: bool = False
    ) -> Organization:
        """
        更新組織資料
        - 管理員：可以更新任何組織
        - 一般使用者：只能更新自己所屬的組織
        """
        org = db.query(Organization).filter(Organization.id == org_id).first()
        if not org:
            raise HTTPException(status_code=404, detail="Organization not found")

        # 權限檢查
        if not is_admin and user_org_id != org_id:
            raise HTTPException(
                status_code=403,
                detail="You can only update your own organization"
            )

        # 更新資料
        for key, value in data.dict(exclude_unset=True).items():
            setattr(org, key, value)

        db.commit()
        db.refresh(org)
        return org
```

#### 4. 不同的 Router

```python
# app/routes/org_profile.py (系統管理員用)
from fastapi import APIRouter, Depends
from app.services.organization_service import OrganizationService

router = APIRouter()

@router.get("/")
async def get_all_organizations(
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
    service: OrganizationService = Depends()
):
    """取得所有組織（管理員專用）"""

    # 檢查是否為管理員
    if not has_permission(current_user, 'org_profile', 'read'):
        raise HTTPException(status_code=403, detail="Permission denied")

    # 管理員可以看到所有組織
    orgs = await service.get_all(db, is_admin=True)

    # 記錄日誌
    await log_user_action(
        current_user.id,
        'org_profile',  # 使用 org_profile
        'View',
        {}
    )

    return orgs

@router.put("/{org_id}")
async def update_organization(
    org_id: int,
    data: OrganizationUpdate,
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
    service: OrganizationService = Depends()
):
    """更新組織資料（管理員專用）"""

    if not has_permission(current_user, 'org_profile', 'update'):
        raise HTTPException(status_code=403, detail="Permission denied")

    # 管理員可以更新任何組織
    updated = await service.update(db, org_id, data, is_admin=True)

    await log_user_action(
        current_user.id,
        'org_profile',  # 使用 org_profile
        'Update',
        updated
    )

    return updated
```

```typescript
import api from './api';

export interface Organization {
  id: number;
  org_code: string;
  org_name: string;
  // ... 其他欄位
}

// 給 org_profile 使用（管理員）
export const getAllOrganizations = async (): Promise<Organization[]> => {
  const response = await api.get('/api/org_profile/');
  return response.data;
};

export const updateOrganizationAdmin = async (
  orgId: number,
  data: Partial<Organization>
): Promise<Organization> => {
  const response = await api.put(`/api/org_profile/${orgId}`, data);
  return response.data;
};

// 給 organizations 使用（一般使用者）
export const getMyOrganization = async (): Promise<Organization[]> => {

  return response.data;

  orgId: number,
  data: Partial<Organization>

  const response = await api.put(`/api/organizations/${orgId}`, data);
```

| 項目 | org_profile (管理員) | organizations (一般使用者) |
|------|---------------------|--------------------------|
| **func_code** | org_profile | organizations |
| **module_code** | org_profile | organizations |
| **Model** | Organization（共用） | Organization（共用，同一個！） |
| **資料表** | organization | organization（同一個） |
| **前端路由** | /org_profile | /organizations |
| **後端 API** | /api/org_profile | /api/organizations |
| **Service** | OrganizationService（共用，is_admin=True） | OrganizationService（共用，is_admin=False） |
| **Router** | org_profile.py（使用 Organization Model） | organizations.py（使用 Organization Model） |

| **資料範圍** | 所有組織 | 只有自己所屬組織 |
| **CRUD 權限** | 完整的 CRUD | 受限的 CRUD |

## 關鍵設計要點

### 1. Service 層的業務邏輯分離

```python
# 使用參數控制業務邏輯
async def get_all(
    self,
    db: Session,
    user_org_id: Optional[int] = None,  # 使用者組織ID
    is_admin: bool = False               # 是否為管理員模式
):
    query = db.query(Organization)

    # 根據不同模式套用不同的過濾條件
    if not is_admin and user_org_id:
        query = query.filter(Organization.id == user_org_id)

    return query.all()
```

### 2. 權限檢查使用不同的 func_code

```python
# org_profile 路由
if not has_permission(current_user, 'org_profile', 'read'):
    raise HTTPException(status_code=403)

# organizations 路由
if not has_permission(current_user, 'organizations', 'read'):
```

### 3. 日誌記錄使用不同的 func_code

```python
# org_profile
await log_user_action(user_id, 'org_profile', 'Update', data)
```

## 優點

1. **權限清晰**：不同功能有獨立的權限控制
2. **業務邏輯分離**：透過參數控制不同的業務規則
3. **程式碼重用**：Model 和 Service 可以共用
4. **日誌追蹤**：可以區分不同功能的操作記錄
5. **擴展性好**：未來可以輕鬆新增更多使用同一資料表的功能

## 注意事項

1. **Service 層設計**：確保 Service 方法支援不同的業務邏輯參數
2. **權限檢查**：每個 Router 都要獨立檢查對應的 func_code 權限
3. **資料過濾**：在 Service 層實作資料範圍限制，不要依賴前端
4. **日誌記錄**：使用正確的 func_code 記錄操作日誌
5. **UI 設計**：前端頁面要清楚區分不同的使用場景
