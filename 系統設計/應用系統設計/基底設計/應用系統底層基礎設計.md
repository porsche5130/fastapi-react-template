## 專案資訊

- **專案名稱**: Paris Agreement Article 6.4 管理系統
- **專案代碼**: PA6.4
- **文件版本**: 1.0.0

## 設計理念

本文檔定義了所有 Python FastAPI 應用系統的標準底層架構，包含 22 個核心功能模組。此架構設計為可重用的基礎模板，適用於任何需要使用者管理、權限控制、多租戶支援的企業級應用系統。

### 核心價值

1. **標準化**: 統一的功能架構，降低學習成本
2. **可重用性**: 適用於所有新專案的起點
3. **可擴展性**: 預留擴充空間，支援專案特定需求
4. **多租戶支援**: 內建組織隔離機制
5. **完整性**: 涵蓋使用者管理、權限控制、系統設定等基礎功能

## 架構設計原則

### 1. ID 分區管理

| ID 範圍 | 用途                           | 管理方式 |
| ------- | ------------------------------ | -------- |
| 1-9     | 外部通用功能（不在功能選單中） | 手動控制 |
| 10+     | 功能選單項目                   | 自動編號 |

**說明**:

- ID 1-9 保留給登入、登出、個人資料等通用功能
- ID 10 開始為功能選單顯示項目
- 使用 PostgreSQL sequence 自動生成 ID 10+

### 2. func_order 分類體系

| func_order | 功能分類     | 說明                   |
| ---------- | ------------ | ---------------------- |
| 1-9        | 外部通用功能 | 登入、登出、個人資料等 |
| 10-69      | 專案特定功能 | 各專案自行定義         |
| 70-79      | 多租戶管理   | 組織管理者功能         |
| 80-89      | 標準化設定   | 系統共用設定           |
| 90-99      | 系統管理後台 | 系統管理員功能         |

**排序規則**:

- 功能選單按 `func_order` 升序排列
- 相同 `func_order` 前綴的功能會分組顯示
- 子功能的 `func_order` 格式: `父功能order + 序號` (例: 9010, 9020, 9030...)

### 3. 資料完整性約束

```sql
-- func_type 約束
CHECK (func_type IN (1, 2))

-- module_code 約束
CHECK (
    (func_type = 1 AND module_code IS NULL) OR
    (func_type = 2 AND module_code IS NOT NULL)
)
```

**說明**:

- `func_type = 1`: 節點（父功能），`module_code` 必須為 `NULL`
- `func_type = 2`: 功能（子功能），`module_code` 不可為 `NULL`

### 4. func_code vs module_code 設計

| 欄位        | 用途                         | 特性                         |
| ----------- | ---------------------------- | ---------------------------- |
| func_code   | 權限識別、前端路由、日誌記錄 | 唯一、不可重複               |
| module_code | API 路由、後端模組對應       | 可重複（多功能共用同一模組） |

**共用模組範例**:

```
func_code: organizations     → module_code: organizations  (系統管理員)
func_code: tenant_profile    → module_code: organizations  (組織管理員)

func_code: users             → module_code: users  (系統管理員)
func_code: tenant_users      → module_code: users  (組織管理員)
```

## 資料庫設計

### system_functions 資料表結構

```sql
CREATE TABLE system_functions (
    id SERIAL PRIMARY KEY,
    func_code VARCHAR(200) NOT NULL,                    -- 功能代碼（唯一）
    upper_func_id INTEGER NOT NULL DEFAULT 0,           -- 父功能ID（0表示根節點）
    func_cname VARCHAR(200) NOT NULL,                   -- 功能中文名稱
    func_ename VARCHAR(200) NOT NULL,                   -- 功能英文名稱
    func_type INTEGER NOT NULL,                         -- 功能類型（1:節點, 2:功能）
    func_order INTEGER NOT NULL,                        -- 顯示順序
    func_icon VARCHAR(200),                             -- 圖示
    module_code VARCHAR(200),                           -- 模組代碼（API路由對應）
    module_item JSONB NOT NULL DEFAULT '[]'::jsonb,     -- 模組項目（CRUD權限）
    description TEXT,                                   -- 說明
    is_mana BOOLEAN NOT NULL DEFAULT false,             -- 是否為管理功能
    is_active BOOLEAN NOT NULL DEFAULT true,            -- 是否啟用
    edit_by INTEGER NOT NULL,                           -- 編輯人員
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP,

    -- 約束
    CONSTRAINT chk_func_type CHECK (func_type IN (1, 2)),
    CONSTRAINT chk_system_functions_module CHECK (
        (func_type = 1 AND module_code IS NULL) OR
        (func_type = 2 AND module_code IS NOT NULL)
    ),

    -- 索引
    INDEX idx_system_functions_code (func_code),
    INDEX idx_system_functions_upper (upper_func_id),
    INDEX idx_system_functions_type (func_type),
    INDEX idx_system_functions_active (is_active),
    INDEX idx_system_functions_order (func_order)
);
```

## 多租戶架構設計

### 核心概念

**多租戶 (Multi-Tenancy)**: 一套系統服務多個組織，每個組織的資料完全隔離。

### 實作方式

#### 1. 共用資料表設計

所有租戶共用相同的資料表，透過 `organization_id` 區分資料所屬。

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    organization_id INTEGER NOT NULL,  -- 組織識別
    account VARCHAR(50) NOT NULL,
    user_name VARCHAR(100) NOT NULL,
    -- ... 其他欄位
);

CREATE INDEX idx_users_org ON users(organization_id);
```

#### 2. 權限隔離機制

| 角色       | 權限範圍         | 使用功能             |
| ---------- | ---------------- | -------------------- |
| 系統管理員 | 所有組織的資料   | system_mana 下的功能 |
| 組織管理員 | 僅自己組織的資料 | tenants 下的功能     |
| 一般使用者 | 僅自己的資料     | 外部通用功能         |

#### 3. API 過濾邏輯

```python
# 系統管理員 - 查詢所有組織
@router.get("/api/organizations")
async def get_organizations(current_user: User = Depends(get_current_user)):
    # 系統管理員可以看到所有組織
    return db.query(Organization).all()

# 組織管理員 - 僅查詢自己的組織
@router.get("/api/tenant_profile")
async def get_tenant_profile(current_user: User = Depends(get_current_user)):
    # 僅查詢當前使用者所屬組織
    return db.query(Organization).filter(
        Organization.id == current_user.organization_id
    ).first()
```

#### 4. 功能對應

| 系統管理功能          | 租戶管理功能           | 共用模組      | 差異         |
| --------------------- | ---------------------- | ------------- | ------------ |
| organizations (ID 12) | tenant_profile (ID 25) | organizations | 過濾條件不同 |
| users (ID 14)         | tenant_users (ID 26)   | users         | 過濾條件不同 |

## 權限控制設計

### 權限層級

```
使用者 (users)
    ↓ 屬於
角色 (user_role)
    ↓ 擁有
功能權限 (role_right)
    ↓ 對應
系統功能 (system_functions)
```

### role_right 資料表

```sql
CREATE TABLE role_right (
    id SERIAL PRIMARY KEY,
    role_id INTEGER NOT NULL,           -- 角色ID
    function_id INTEGER NOT NULL,       -- 功能ID (system_functions.id)
    can_create BOOLEAN DEFAULT false,   -- 新增權限
    can_read BOOLEAN DEFAULT false,     -- 查詢權限
    can_update BOOLEAN DEFAULT false,   -- 修改權限
    can_delete BOOLEAN DEFAULT false,   -- 刪除權限
    can_print BOOLEAN DEFAULT false,    -- 列印權限
    can_file BOOLEAN DEFAULT false,     -- 檔案權限

    FOREIGN KEY (role_id) REFERENCES user_role(id),
    FOREIGN KEY (function_id) REFERENCES system_functions(id),
    UNIQUE (role_id, function_id)
);
```

### 權限檢查流程

```python
def check_permission(user_id: int, func_code: str, action: str) -> bool:
    """
    檢查使用者是否有特定功能的操作權限

    Args:
        user_id: 使用者ID
        func_code: 功能代碼
        action: 操作類型 (create/read/update/delete/print/file)

    Returns:
        bool: 是否有權限
    """
    # 1. 取得使用者角色
    user = db.query(User).filter(User.id == user_id).first()

    # 2. 取得功能ID
    function = db.query(SystemFunction).filter(
        SystemFunction.func_code == func_code
    ).first()

    # 3. 查詢角色權限
    right = db.query(RoleRight).filter(
        RoleRight.role_id == user.role_id,
        RoleRight.function_id == function.id
    ).first()

    # 4. 檢查特定操作權限
    if action == 'create':
        return right.can_create
    elif action == 'read':
        return right.can_read
    # ... 其他操作

    return False
```
