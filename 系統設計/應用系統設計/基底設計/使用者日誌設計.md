## 1. 功能概述

### 1.1 模組名稱
**user_logs** - 使用者作業日誌記錄模組

### 1.2 功能說明
本模組用於記錄系統中所有使用者的操作行為，包括新增、檢視、修改、刪除等作業，以及操作過程中的錯誤訊息。當 `user_logs` 的 `is_active=true` 時，系統會自動記錄所有使用者的操作軌跡。

### 1.3 設計目標
- 完整記錄使用者操作歷程
- 提供資料異動追溯機制
- 記錄系統錯誤便於問題排查
- 支援資料稽核與合規要求

### 1.4 日誌記錄策略與原則

#### 1.4.1 記錄原則
本系統採用「**只記錄有實質影響的操作**」原則，避免產生過多無意義的日誌記錄：

✅ **應該記錄的操作**（對系統有實質影響）：
- **Create** - 新增資料（資料庫有變更）
- **Update** - 修改資料（資料庫有變更）
- **Delete** - 刪除資料（資料庫有變更）
- **Login** - 登入行為（安全稽核需要）
- **Print** - 列印操作（可能涉及敏感資料外洩）
- **File** - 檔案上傳/下載（可能涉及敏感資料）
- **View** - 功能瀏覽記錄（使用者進入功能頁面）
- **Read** - 資料檢視記錄（查看單筆資料詳情）

#### 1.4.2 View 與 Read 的區別

**View（功能瀏覽記錄）**：
- **時機點**：使用者進入功能頁面時（呼叫列表 API：`GET /api/xxx/`）
- **記錄內容**：查詢條件、篩選參數（`look_data`）
- **核心意義**：記錄使用者「進入並瀏覽」某個功能
- **實際用途**：
  - 權限稽核：追蹤使用者是否真的在使用被授予的功能權限
  - 使用統計：了解哪些功能被頻繁使用、哪些沒人用
  - 異常追蹤：即使後續查詢失敗，也有進入記錄

**Read（資料檢視記錄）**：
- **時機點**：使用者查看特定單筆資料詳情時（呼叫單筆 API：`GET /api/xxx/{id}`）
- **記錄內容**：實際查看的完整資料內容（`look_data`）
- **核心意義**：記錄使用者「檢視特定資料」的行為
- **實際用途**：
  - 安全追蹤：追溯誰查看過哪些敏感資料
  - 資料稽核：記錄特定資料被誰存取過
  - 行為分析：了解使用者對哪些資料有興趣

**兩者的關係**：
```
使用者進入組織管理頁面 → View (功能瀏覽)
  ↓
點擊「總公司」查看詳情 → Read (資料檢視)
```

#### 1.4.3 不同系統的日誌需求差異

**一般管理系統**（本系統）：
- ✅ Create/Update/Delete - 必須記錄
- ✅ Login - 必須記錄
- ✅ View（進入功能） - 記錄以追蹤功能使用
- ✅ Read（查看詳情） - 記錄以追蹤資料存取

**金融/醫療/高敏感系統**：
- ✅ 所有操作都要記錄（包含列表查詢）
- 需要更細緻的 module_item 設計：
  - ReadList - 查詢列表
  - ReadDetail - 查看詳情
  - ReadSensitive - 查看敏感欄位
  - Export - 匯出資料
  - 等等...

#### 1.4.4 Session ID 追蹤

為了追蹤同一次登入 session 的所有操作，系統實作了 Session ID 機制：

- 使用者登入時產生唯一的 Session ID（UUID 格式）
- Session ID 存入 JWT token 的 payload 中
- 每次 API 請求時，從 token 提取 Session ID 並透過 ContextVar 傳遞
- 所有日誌記錄都包含 Session ID，可追蹤單一 session 的完整操作軌跡

**Session ID 的價值**：
- 可以追蹤使用者「這次登入」做了哪些操作
- 區分不同裝置/瀏覽器的登入行為
- 有助於異常行為偵測（例如：同一個帳號在短時間內從不同 session 執行大量操作）

## 2. 資料表設計

### 2.1 資料表：user_logs (作業紀錄表)

| 欄位編號 | 欄位名稱 | 資料型態 | 長度 | 約束條件 | 預設值 | 說明 |
|---------|---------|---------|------|---------|--------|------|
| 1 | id | SERIAL | - | PK, NOT NULL | AUTO | 資料編號（自動編號）|
| 2 | user_id | INTEGER | - | NOT NULL, FK | - | 作業人員（關聯 users.id）|
| 3 | session_id | VARCHAR | 36 | NULL | NULL | 登入 Session 識別碼（UUID）|
| 4 | system_function_id | INTEGER | - | NOT NULL, FK | - | 作業功能（關聯 system_functions.id）|
| 5 | module_item | VARCHAR | 50 | NOT NULL, CHECK | - | 模組項目：Create, Read, Update, Delete, Print, File, Login, View |
| 6 | look_data | JSONB | - | NULL | {} | 檢視資料（JSON 格式，欄位名稱:資料內容）|
| 7 | change_data | JSONB | - | NULL | {} | 異動資料（JSON 格式，欄位名稱:資料內容）|
| 8 | action_at | TIMESTAMP | - | NOT NULL | NOW() | 作業時間 |
| 9 | err_detail | VARCHAR | 2000 | NULL | NULL | 異常紀錄 |

```sql
-- 主鍵索引（自動建立）

-- 作業功能索引（常用查詢）
```

## 3. 作業邏輯設計

### 3.1 日誌啟用條件

```python
# 檢查是否啟用日誌記錄
def is_logging_enabled(db: Session) -> bool:
    """
    檢查 user_logs 功能的 is_active 狀態
    當 system_functions 表中 func_code='user_logs' 且 is_active=true 時啟用
    """
    user_logs_func = db.query(SysFunction).filter(
        SysFunction.func_code == 'user_logs',
        SysFunction.is_active == True
    ).first()
    return user_logs_func is not None
```

### 3.2 Session ID 管理

**Session ID 的產生與傳遞**：

1. **登入時產生**：
```python
# app/routes/auth.py
import uuid
from app.core.deps import session_id_ctx

@router.post("/login")
async def login(...):
    # 產生 Session ID (UUID)
    session_id = str(uuid.uuid4())

    # 設定到 context（用於記錄登入日誌）
    session_id_ctx.set(session_id)

    # 將 session_id 寫入 JWT token
    access_token = create_access_token(data={
        "sub": str(user.id),
        "session_id": session_id
    })

    return {"access_token": access_token, ...}
```

2. **每次請求時提取**：
```python
# app/core/deps.py
from contextvars import ContextVar

# 定義 ContextVar 用於存放 session_id
session_id_ctx: ContextVar[Optional[str]] = ContextVar("session_id", default=None)

def get_current_user(...):
    # 從 JWT token 提取 session_id
    session_id = payload.get("session_id")

    if session_id:
        # 設定到 context，供後續日誌記錄使用
        session_id_ctx.set(session_id)
    else:
        # 舊 token 沒有 session_id，產生臨時的
        temp_session_id = f"legacy-{uuid.uuid4()}"
        session_id_ctx.set(temp_session_id)
```

3. **記錄日誌時使用**：
```python
# app/services/user_logs_service.py
from app.core.deps import session_id_ctx

def create_log(...):
    # 從 context 取得 session_id
    session_id = session_id_ctx.get()

    log = UserLog(
        users_id=user_id,
        system_functions_id=function_id,
        module_item=module_item,
        session_id=session_id,  # 寫入 session_id
        look_data=look_data or {},
        change_data=change_data or {},
        action_at=datetime.now(),
        err_detail=err_detail
    )
    ...
```

### 3.4 View 操作記錄（功能瀏覽記錄）

**邏輯說明**：
- 當使用者進入功能頁面時（通過權限檢查後立即記錄）
- 記錄使用者的功能瀏覽行為，代表「使用者確實啟動並進入了這個功能」
- 將查詢條件和操作資訊轉換為 JSON 格式
- 寫入 `look_data` 欄位
- `change_data` 保持為空物件 `{}`

**記錄時機點**：
```
請求 → JWT驗證 → 權限檢查通過 → ✅ 記錄 View 日誌 → 執行查詢 → 回傳結果
                  ↓ 403 Forbidden
              權限檢查失敗（不記錄）
```

**資料格式範例**：
```json
{
  "look_data": {
    "action": "view_list",
    "filters": {
      "skip": 0,
      "limit": 100,
      "is_active": true,
      "search": "總公司"
    }
  },
  "change_data": {}
}
```

**實作範例**：
```python
@router.get("/", response_model=List[OrganizationResponse])
async def get_organizations(
    skip: int = 0,
    limit: int = 100,
    is_active: Optional[bool] = None,
    search: Optional[str] = None,
    db: Session = Depends(get_db),
    current_user: UserDetail = Depends(get_current_user)
):
    # 1. 檢查權限
    if not check_permission(db, current_user, "organizations", "read"):
        raise HTTPException(status_code=403, detail="無權限")

    # 2. 權限檢查通過後，立即記錄 View 日誌
    try:
        function_id = UserLogService.get_function_id_by_code(db, "organizations")
        if function_id:
            UserLogService.log_view(
                db=db,
                user_id=current_user.id,
                function_id=function_id,
                viewed_data={
                    "action": "view_list",
                    "filters": {
                        "skip": skip,
                        "limit": limit,
                        "is_active": is_active,
                        "search": search
                    }
                },
                current_user=current_user
            )
    except Exception as e:
        logger.error(f"日誌記錄失敗: {e}")

    # 3. 執行實際查詢
    query = db.query(Organization)
    if is_active is not None:
        query = query.filter(Organization.is_active == is_active)
    if search:
        query = query.filter(
            (Organization.org_code.ilike(f"%{search}%")) |
            (Organization.org_name.ilike(f"%{search}%"))
        )
    organizations = query.order_by(Organization.id).offset(skip).limit(limit).all()

    return organizations
```

### 3.5 Read 操作記錄（資料檢視記錄）

**邏輯說明**：
- 當使用者查看單筆資料詳情時記錄（查詢後記錄）
- 記錄使用者對特定資料的檢視行為
- 將完整的資料內容轉換為 JSON 格式
- 寫入 `look_data` 欄位
- `change_data` 保持為空物件 `{}`

**與 View 的區別**：
- **View**：功能瀏覽，記錄「進入功能」（權限檢查後，查詢前）
- **Read**：資料檢視，記錄「查看具體資料」（查詢後）

**資料格式範例**：
```json
{
  "look_data": {
    "id": 123,
    "org_code": "ORG001",
    "org_cname": "總公司",
    "org_ename": "Headquarters",
    "org_type": 1,
    "is_active": true,
    "created_at": "2026-01-20T10:30:00",
    "updated_at": "2026-01-20T15:45:00"
  },
  "change_data": {}
}
```

**實作範例**：
```python
@router.get("/{org_id}", response_model=OrganizationResponse)
async def get_organization(
    org_id: int,
    db: Session = Depends(get_db),
    current_user: UserDetail = Depends(get_current_user)
):
    # 1. 檢查權限
    if not check_permission(db, current_user, "organizations", "read"):
        raise HTTPException(status_code=403, detail="無權限")

    # 2. 執行查詢
    org = db.query(Organization).filter(Organization.id == org_id).first()
    if not org:
        raise HTTPException(status_code=404, detail="找不到組織")

    # 3. 查詢成功後，記錄 Read 日誌
    try:
        function_id = UserLogService.get_function_id_by_code(db, "organizations")
        if function_id:
            UserLogService.log_read(
                db=db,
                user_id=current_user.id,
                function_id=function_id,
                viewed_data=organization_to_dict(org),  # 記錄完整資料
                current_user=current_user
            )
    except Exception as e:
        logger.error(f"日誌記錄失敗: {e}")

    return org
```

### 3.5 Update 操作記錄

**邏輯說明**：
- 當使用者執行修改操作時
- 將修改**前**的資料轉換為 JSON，寫入 `look_data`
- 將修改**後**的資料轉換為 JSON，寫入 `change_data`
- 兩者皆不為 NULL

**資料格式範例**：
```json
{
  "look_data": {
    "id": 123,
    "org_code": "ORG001",
    "org_cname": "總公司",
    "org_ename": "Headquarters",
    "is_active": true
  },
  "change_data": {
    "id": 123,
    "org_code": "ORG001",
    "org_cname": "總公司（台北）",
    "org_ename": "Headquarters (Taipei)",
    "is_active": true
  }
}
```

**實作範例**：
```python
async def log_update_action(
    db: Session,
    user_id: int,
    function_id: int,
    original_data: dict,
    updated_data: dict
):
    """記錄 Update 操作"""

        module_item="Update",

        change_data=updated_data,

    db.add(log)
    db.commit()
```

### 3.9 Login 操作記錄

**邏輯說明**：
- 當使用者執行登入操作時
- 記錄登入資訊（使用者名稱、登入時間、IP 位址等）
- 寫入 `change_data` 欄位
- `look_data` 保持為空物件 `{}`
- **同時產生並記錄 session_id**

**資料格式範例**：
```json

  "change_data": {
    "username": "admin",
    "login_at": "2026-01-20T10:30:00",
    "ip_address": "192.168.1.100",
    "user_agent": "Mozilla/5.0..."
  },
  "look_data": {},
  "session_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}
```

**實作範例**：
```python
import uuid
from app.core.deps import session_id_ctx

async def log_login_action(
    db: Session,
    user_id: int,
    function_id: int,
    login_info: dict
):
    """記錄 Login 操作"""
    if not is_logging_enabled(db):
        return

    # 產生 Session ID

        module_item="Login",
        session_id=session_id,
        look_data={},
        change_data=login_info,
        action_at=datetime.now()
    )
    db.add(log)
    db.commit()
```

```python
from sqlalchemy.orm import Session
from sqlalchemy import and_
from typing import Dict, Any, Optional
from datetime import datetime
from app.models.user_logs import UserLog
from app.models.system_functions import SysFunction

class UserLogService:
    """使用者日誌服務"""

    @staticmethod
    def is_logging_enabled(db: Session) -> bool:
        """檢查是否啟用日誌記錄"""
        user_logs_func = db.query(SysFunction).filter(
            SysFunction.func_code == 'user_logs',
            SysFunction.is_active == True
        ).first()
        return user_logs_func is not None

    @staticmethod
    def create_log(
        db: Session,
        user_id: int,
        function_id: int,
        module_item: str,
```

```python
router = APIRouter()

@router.get("/", response_model=List[UserLogSchema], summary="取得使用者日誌列表")
async def get_user_logs(
    users_id: Optional[int] = Query(None, description="作業人員ID"),
    system_functions_id: Optional[int] = Query(None, description="作業功能ID"),
    module_item: Optional[str] = Query(None, description="模組項目"),
    start_date: Optional[datetime] = Query(None, description="開始日期時間"),
    end_date: Optional[datetime] = Query(None, description="結束日期時間"),
    skip: int = Query(0, ge=0, description="略過筆數"),
    limit: int = Query(100, ge=1, le=1000, description="取得筆數"),
    db: Session = Depends(get_db),
    current_user: UserDetail = Depends(get_current_user)
):
    """
    取得使用者日誌列表（支援多條件查詢）
    """
    # 建立查詢條件
    conditions = []
    if users_id:
        conditions.append(UserLog.users_id == users_id)
    if system_functions_id:
        conditions.append(UserLog.system_functions_id == system_functions_id)
    if module_item:
        conditions.append(UserLog.module_item == module_item)
    if start_date:
        conditions.append(UserLog.action_at >= start_date)
    if end_date:
        conditions.append(UserLog.action_at <= end_date)

    # 查詢
    query = db.query(UserLog)
    if conditions:
        query = query.filter(and_(*conditions))

    # 排序並分頁
    logs = query.order_by(desc(UserLog.action_at)).offset(skip).limit(limit).all()
    return logs
```

## 6. 資料保留政策

### 6.1 保留期限建議
- **一般日誌**：保留 1 年
- **異常日誌**：保留 2 年
- **敏感操作日誌**（刪除、權限變更等）：保留 3 年

### 6.2 歸檔策略

```sql
-- 建立歷史資料表
CREATE TABLE user_logs_archive (LIKE user_logs INCLUDING ALL);

-- 歸檔超過一年的資料
INSERT INTO user_logs_archive
SELECT * FROM user_logs
WHERE action_at < NOW() - INTERVAL '1 year'
  AND err_detail IS NULL;

-- 刪除已歸檔資料
DELETE FROM user_logs
WHERE action_at < NOW() - INTERVAL '1 year'
  AND err_detail IS NULL;
```

1. 使用批次寫入減少資料庫連線

4. 實作日誌佇列機制

## 8. 安全性考量

### 8.1 敏感資料處理
- 密碼欄位不得記錄在日誌中
- 個人敏感資料需經過遮罩處理
- Token 和 Session 資訊不得記錄

### 8.2 存取控制
- 只有系統管理員可查看所有日誌
- 一般使用者只能查看自己的操作記錄
- 稽核人員有唯讀權限
