## 📦 建議的檔案保存策略

### 立即刪除 (低風險)
- ✅ `__pycache__/` 目錄
- ✅ `.pyc` 檔案

### 短期保留 (1-2週)
- ⏱️ 舊版 `.old` 檔案
- ⏱️ 過程性文件 (可移至 archive/)

### 長期保留 (1-2個月)
- 📁 備份腳本
- 📁 遷移腳本
- 📁 核心文件 (BASELINE_VERIFICATION.md 等)

### 永久保留
- 🔒 BASELINE_VERIFICATION.md
- 🔒 NAMING_STANDARDS.md
- 🔒 系統設計/應用系統設計/基底設計/*.md

## 🚀 執行清理步驟

### 步驟 1: 建立歸檔目錄
```bash
cd W:\P-PA6.4\Develop
mkdir -p archive/{backup_scripts,migration_scripts,old_models,old_routes,process_docs}
```

### 步驟 2: 移動暫存檔案
```bash
# 備份腳本
mv backup_database.py archive/backup_scripts/
mv backup_database_sql.py archive/backup_scripts/

# 遷移腳本
mv drop_old_tables.sql archive/migration_scripts/

# 過程文件
mv COMPLETION_REPORT.md archive/process_docs/
mv DATABASE_INTEGRATION_CONFIRMED.md archive/process_docs/
mv DEPLOYMENT_CHECKLIST.md archive/process_docs/
mv DEPLOYMENT_GUIDE.md archive/process_docs/
mv FINAL_VERIFICATION.md archive/process_docs/
mv IMPLEMENTATION_CHECKLIST.md archive/process_docs/
mv REFACTORING_SUMMARY.md archive/process_docs/
mv RENAME_SYSFUCTION_TO_SYSFUNCTION.md archive/process_docs/
mv TABLE_MIGRATION_SUMMARY.md archive/process_docs/
mv VERIFICATION_REPORT.md archive/process_docs/
mv 角色權限設定作業_開發完成報告.md archive/process_docs/
mv 前端開發完成說明.md archive/process_docs/
```

### 步驟 3: 清理 Python 編譯檔
```bash
cd W:\P-PA6.4\Develop\backend
find . -type d -name "__pycache__" -exec rm -rf {} +
find . -type f -name "*.pyc" -delete
```

### 步驟 4: 處理舊版檔案 (謹慎執行)
```bash
# 檢查是否存在
cd W:\P-PA6.4\Develop\backend\app\models
ls -la *.old

# 如果存在,移動至歸檔
mv *.old W:\P-PA6.4\Develop\archive\old_models/ 2>/dev/null

cd W:\P-PA6.4\Develop\backend\app\routes
ls -la *.old
mv *.old W:\P-PA6.4\Develop\archive\old_routes/ 2>/dev/null
```

## ⚠️ 注意事項

1. **執行前請先備份整個專案**
   ```bash
   cd W:\P-PA6.4
   git add -A
   git commit -m "清理前備份"
   ```

2. **分階段執行**
   - 不要一次刪除所有檔案
   - 每次刪除後測試系統運行是否正常

3. **保留 Git 歷史**
   - 所有已提交的檔案在 Git 歷史中仍可找回
   - 可使用 `git log --all --full-history -- <檔案路徑>` 查詢

4. **資料庫備份**
   - 刪除備份腳本前，確認已有完整的資料庫備份
   - 建議保留最新備份: `backups/pa64_dev_backup_20260123_053610.sql`
