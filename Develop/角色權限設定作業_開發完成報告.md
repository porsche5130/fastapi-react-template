## 三、資料表設計

### role_right (角色權限設定檔)

```sql
-- 主鍵
id                SERIAL PRIMARY KEY

-- 關聯欄位
user_role_id      INTEGER NOT NULL (FK -> user_role.id)
sysfuction_id     INTEGER NOT NULL (FK -> sysfuction.id)
func_code         VARCHAR(20) NOT NULL

-- 權限設定
is_create         BOOLEAN NOT NULL DEFAULT FALSE
is_read           BOOLEAN NOT NULL DEFAULT FALSE
is_update         BOOLEAN NOT NULL DEFAULT FALSE
is_delete         BOOLEAN NOT NULL DEFAULT FALSE
is_print          BOOLEAN NOT NULL DEFAULT FALSE
is_file           BOOLEAN NOT NULL DEFAULT FALSE

-- 系統欄位
edit_by           INTEGER NOT NULL (FK -> user_detail.id)
created_at        TIMESTAMP NOT NULL
updated_at        TIMESTAMP

-- 索引
idx_role_right_role                  (user_role_id)
idx_role_right_function              (sysfuction_id)
idx_role_right_unique (UNIQUE)       (user_role_id, sysfuction_id)
```

**約束說明**:
- 唯一性約束: `(user_role_id, sysfuction_id)` - 一個角色對一個功能只能有一組權限
- CASCADE DELETE: 當角色或功能被刪除時，相關權限自動刪除

## 四、API 設計

### 4.1 取得功能清單與可用權限
```
GET /api/role_right/functions
```
- 回傳所有已啟用的功能
- 包含每個功能的 available_permissions (哪些權限可設定)

### 4.2 取得角色權限設定
```
GET /api/role_right/{role_id}
```
- 取得指定角色的權限設定
- 回傳角色資訊與權限列表

### 4.3 儲存角色權限設定
```
POST /api/role_right/{role_id}
Body: { "rights": [...] }
```
- **先刪後增策略**: 刪除舊資料後批次新增
- 避免資料誤植，確保一致性

### 4.4 刪除角色權限設定
```
DELETE /api/role_right/{role_id}
```
- 刪除指定角色的所有權限設定

## 七、權限檢查工具

### 使用方式

```python
from app.core.permissions import check_permission, require_permission

# 方式 1: 直接檢查
has_permission = check_permission(db, user, "organizations", "create")

# 方式 2: 裝飾器
@router.post("/organizations")
@require_permission("organizations", "create")
async def create_organization(...):
    ...
```

### 檢查邏輯
1. 取得使用者的所有角色ID (`user_detail.user_role`)
2. 查詢 `role_right` 表中該角色對指定功能的權限
3. 只要有任一角色擁有權限即可 (OR 邏輯)
